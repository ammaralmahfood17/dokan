## 1. Executive Summary

دكان لم يعد يعاني مشكلة أداء ولا هوية: أحدث قياس مختبري (LHCI، موبايل 360×800، 4× CPU، 1.6Mbps) يسجّل
`/` 1656ms · `/login` 1535ms · `/estikana` 1402ms · قائمة QR 1902ms، وبيانات الحقل الحقيقية اليوم
(LCP p75 = 868ms لـ 199 قياسًا، INP p75 = 56ms، CLS = 0) تسبق أهداف Core Web Vitals بفارق مريح.
المشكلة المتبقية **مشكلة تغطية لا مشكلة جودة**: مصفوفة الاستجابة تحمي 8 مسارات عامة فقط، ولا يوجد
متصفح غير Chromium في أي بوابة (صفر ذكر لـ WebKit في `e2e/` أو `.github/`)، وشاشات التاجر
(POS، المطبخ، الطلبات، الجداول) لا تُقاس تخطيطيًا عند 320 أو 768 أو 1024 — تُقاس فقط بـ axe.
يضاف إلى ذلك دَين مكوّنات محدد: **104 أحجام نص خارج السلّم**، صفر استعلامات `(hover: hover)`
(لذا يبقى تأثير التحويم ملتصقًا على iOS)، صفر breadcrumbs، و`aria-invalid` في 5 ملفات فقط من
نماذج المشروع. الخطة هنا أربع موجات / **15 يوم عمل**: أولًا نوسّع **القياس** (مصفوفة المسارات
المسجّلة + WebKit + لقطات بصرية)، ثم نسدّد دَين التوكنات والنماذج، ثم نُصلح ما سيكشفه iOS
ونضبط INP على POS، وأخيرًا نُغلق التوجيه والحالات الحدّية. الترتيب مقصود: **لا تُصلح ما لا تقيسه**،
ولا تُوسّع نظام التصميم قبل أن يكون كل كسر تخطيطي مرئيًا في بوابة.

**قرارات مثبّتة لا تُعاد مناقشتها:** لا shadcn/ui، لا تغيير لبنية المسارات، لا framer-motion،
الوضع الداكن خارج النطاق بقرار المالك (مُوثّق في §4.3 مع كلفته إن تغيّر القرار).

## 2. Responsive Strategy

### 2.1 الحالة المقاسة اليوم

| المحور | الواقع (مصدره) | الأثر |
|---|---|---|
| نقاط الانكسار | 13 استعلام `@media` في `globals.css`؛ الاستخدامات: `lg:` 64 · `md:` 57 · `sm:` 29 · `xl:` 17 | السلّم مستقر، لا حاجة لإعادة تعريف Tailwind |
| مصفوفة الاختبار | `e2e/responsive.spec.ts`: 7 مقاسات × 8 مسارات **عامة** = 56 خلية، تعمل ليليًا 02:00 UTC | شاشات التاجر ليست في المصفوفة إطلاقًا |
| المتصفحات | `playwright.config.ts` و`quality-watch.yml`: Chromium فقط | **iOS/Safari غير مُختبر** — أكبر فجوة في المشروع |
| التابلت | السكة 88px عند `md`، POS سلة كشريط حتى 1280 (الموجة 1) | يعمل، لكن بلا اختبار انحدار يمنع الرجوع |
| `dvh` | 19 موضعًا (`min-h-dvh` / `h-dvh`) | سليم؛ لا `100vh` متبقٍ |
| المناطق الآمنة | 9 استخدامات لـ `env(safe-area-inset-*)` | تغطي الشريطين السفليين، لا تغطي أي شريط جديد |
| 320px | مُختبر على المسارات العامة فقط | جداول الطلبات وبطاقات KPI غير مُختبرة عند 320 |
| التحويم | **صفر** `(hover: hover)` أو `(pointer: fine)` في CSS، مع 107 انتقالات | hover عالق على اللمس (iOS يُبقي الحالة بعد النقر) |
| breadcrumbs | **صفر** مكوّن أو استخدام | العمق في لوحة التاجر بلا مسار رجوع مرئي |

### 2.2 نقاط الانكسار المعتمدة (تبقى كما في v1)

| Token | العرض | الجهاز | التخطيط |
|---|---|---|---|
| `xs` | 320–359 | iPhone SE | عمود واحد، هامش 12px، لا عمودين KPI |
| base | 360–639 | هاتف | هامش 16px، شريط سفلي 56px |
| `sm` | 640–767 | هاتف كبير | منيو 3 أعمدة |
| `md` | 768–1023 | **تابلت الكاشير/المطبخ** | سكة أيقونات 88px، POS 3 أعمدة + شريط سلة |
| `lg` | 1024–1279 | تابلت أفقي | شريط جانبي 240px، سلة مرساة |
| `xl` | 1280–1535 | لابتوب | حاوية 1280، عمودان للرسوم |
| `2xl` | 1536+ | شاشة واسعة | حاوية 1440 قصوى |

**Mobile-first يبقى القرار**، والسبب تجاري (70%+ زيارات هاتف) وتقني (خصائص منطقية RTL تعمل بالاتجاهين).
لا تغيير على الإستراتيجية؛ التغيير في **من يُختبر**.

### 2.3 ما تُضيفه الموجة 6 تحديدًا

1. **مصفوفة المسارات المسجّلة.** توسيع `e2e/responsive.spec.ts` بجدول ثانٍ `AUTHED_ROUTES`
   (‏`/dashboard`، `/dashboard/pos`، `/dashboard/kitchen`، `/dashboard/orders`،
   `/dashboard/products`، `/dashboard/tables`، `/dashboard/settings`، `/dashboard/analytics`)
   بمقاسات **320 · 768 · 1024 · 1280** + 640×512 (تكبير 200%). يُنفَّذ عبر storageState
   لمستخدم اختباري، لا عبر تسجيل دخول حقيقي في كل خلية (‏`e2e/.auth/user.json`، يُنشأ في
   `globalSetup` ويُحذف بعده).
2. **WebKit.** مشروع ثالث في `playwright.config.ts`:
   ```ts
   { name: 'webkit', testMatch: /(responsive|ios)\.spec\.ts/, use: { ...devices['iPhone 13'] } }
   ```
   مع `npx playwright install --with-deps webkit` في `quality-watch.yml`. ملف `e2e/ios.spec.ts`
   يركز على ثلاثة أشياء فقط: التمرير داخل `100dvh`، تكبير الحقول (<16px ⇒ zoom)، وسلوك
   `position: fixed` مع شريط Safari السفلي.
3. **لقطات بصرية أساسية.** `toHaveScreenshot()` عند 390 و768 و1280 لـ 6 شاشات
   (منيو، POS، KDS، الطلبات، الجداول، الإعدادات). خط أساس واحد يُعتمد بعد مراجعة بشرية،
   وأي فرق لاحق يفشل مع صورة diff — هذا ما يمنع «إصلاح 768 يكسر 1280» بلا أن يراه أحد.
4. **قاعدة التحويم.** كل تأثير hover بصري يُغلَّف:
   ```css
   @media (hover: hover) and (pointer: fine) { .card:hover { … } }
   ```
   أو يُستبدل بـ `:focus-visible` + `:active` على الأجهزة اللمسية.
5. **حد 320px للجداول.** الجداول العريضة (`recent-orders-table`, inventory) تتحول إلى
   `overflow-x: auto` مع `min-width` صريح بدل دفع الصفحة كلها أفقيًا؛ الاختبار موجود بالفعل
   ويفشل عند التجاوز — نحتاج فقط إدخال الشاشات المسجّلة في المصفوفة.

### 2.4 الأرضيات والفتحات والأجهزة القابلة للطي

- الـ 44px ليست قاعدة CSS فقط: `scripts/check-touch-targets.mjs` بوابة CI تفشل عند أي زر أيقوني
  أصغر. تُوسَّع لتشمل `<a>` و`[role=button]` و`summary`.
- `env(safe-area-inset-*)` تُستهلك عبر توكن واحد `--safe-bottom` بدل 9 نسخ متفرقة، وأي شريط سفلي
  جديد يرثه تلقائيًا (قاعدة: `.pb-bottom-nav` هو المصدر الوحيد).
- الأجهزة القابلة للطي (Galaxy Fold 280px مغلق) خارج النطاق المعلن؛ 320 يبقى الأرضية.

## 3. Performance Blueprint

### 3.1 الأهداف والقياس الحالي

| المقياس | الهدف | مختبري (LHCI، Wave 4) | حقل (اليوم، `web_vitals`) | الحكم |
|---|---|---|---|---|
| LCP | < 2.5s | 1402–1902ms | **p75 868ms** (n=199) | ✅ بهامش |
| INP | < 100ms | TBT 600ms كتحذير | **p75 56ms** (n=44، max 344) | ✅ لكن العيّنة صغيرة |
| CLS | < 0.1 | مُقيد عند 0.05 | **p75 0** (n=107) | ✅ مثالي |
| TTFB | < 800ms | — | **p75 239ms** | ✅ (بوم1 + Supabase) |
| الحِزم | 353.9KB أكبر chunk | 61 حزمة / 2067KB | — | ✅ داخل الميزانية |

**أصدق قراءة:** الأرقام خضراء، لكن `n=44` لـ INP لا يكفي لادّعاء. الهدف في الموجة 8 ليس
«تحسين» ما هو جيد، بل **حماية** ما هو جيد عبر عيّنة أكبر + ميزانية أداء لكل مسار.

أضعف مسار حقلًا هو `/` (LCP p75 = 2117ms، n=7) ثم `/dashboard/tables` (1472ms، n=22) — الأول
بسبب صورة الهيرو، والثاني بسبب جدول/بطاقات تُرسم بعد hydration.

### 3.2 ما تبقّى فعليًا (لا إعادة لما أُنجز)

| البند | الحالة | العمل في الموجة 8 |
|---|---|---|
| AVIF/WebP + `sizes` | منفّذ (Wave 4) | art direction للهيرو: `<picture>` بمصدر 4:5 للهاتف و16:9 لسطح المكتب |
| هيرو `/` | LCP 2117ms حقلًا | `priority` + `fetchPriority="high"` + قياس `LCP element` من `web_vitals` |
| POS INP | p75 56ms، max 344ms | `useDeferredValue` لمجموع السلة، `memo` لصفوف الشبكة، وقياس `event.duration` |
| الحِزم | 353.9KB أكبر chunk | `check-js-budget` لكل مسار بدل إجمالي واحد (POS هو المرشح الأول) |
| الخط | 154KB base64 في `public/thmanyah.css` يُحمَّل بعد أول رسم | إبقاء `font-display: swap` + قياس CLS عند أول رسم فعلي (حاليًا صفر) |
| Service Worker | v9، 4 مخازن، سقف 120 مدخلًا، `offline.html` | إضافة **قائمة QR** لمخزن الصفحات (حاليًا لا تُخزَّن، فالمنيو بدون شبكة = صفحة أوفلاين فقط) |
| التدهور اللطيف | `offline-banner` + طابور POS في IndexedDB | لا عمل جديد؛ فقط اختبار WebKit لـ IndexedDB في التصفح الخاص |

### 3.3 CSS containment وGPU

`.chart-container` و`.product-grid` عليهما `contain` بالفعل. المتبقي:
`contain: content` على `.card` داخل الشبكات الطويلة (الطلبات/المنتجات) و`will-change: transform`
**مؤقتًا** على عناصر الشريحة أثناء السحب فقط (لا `will-change` دائم — يستهلك ذاكرة GPU على أجهزة 2GB).
القاعدة: لا `transform` على حاوية تحمل `position: fixed` (درس موثّق في `page-enter`).

### 3.4 OFFLINE — تقييم الموجود

الـSW الحالي: precache للصدفة + بناء Next من HTML الرئيسية + RSC caching + push + سقف تخزين.
ناقص: (1) قائمة QR ليست في أي مخزن، (2) لا `Background Sync` (قرار صحيح لـSafari)،
(3) لا تمييز بين «لا شبكة» و«الخادم عاد 500» في واجهة المنيو — كلاهما يُظهر نفس الشاشة.

## 4. Design System Specification

### 4.1 التوكنات — الحالة

`@theme` يحمل اليوم: ألوان العلامة (violet #7047EB)، محايدات دافئة (#FAF9F6)، دلالات
(success/warn/danger/info + tints)، حدود (`border` / `border-strong` / `border-control`)،
نص بأربع درجات، ستة أدوار طباعية بـ`clamp()`، حاويات (720/1280/1440)، أنصاف أقطار
(6/10/14/20/999)، ظلّان (`float`, `focus`)، z-index بتسع طبقات، وحركة
(100/150/200/240ms + `cubic-bezier(.2,0,0,1)`). هذا الجزء **مكتمل ولا يُعاد تصميمه**.

### 4.2 الألوان — لماذا تبقى

كل لون محمي باختبار تباين (`contrast.test.ts` + `design-tokens.test.ts` + `contrast.ts`):
الأساسي 5.26:1 على الخلفية و5.54:1 مع الأبيض، `text-secondary` 5.12:1، `danger` 6.4:1.
**لا نلمس القيم**؛ أي تغيير يهدم 9 اختبارات وعقد توكينات المستأجر (9 ألوان × 4 أسطح).

### 4.3 الوضع الداكن — قرار صريح وكلفته

المنتج `color-scheme: light` بقرار موثّق (F-20). تنفيذ وضع داكن ليس «إضافة صنف»:
يلزمه (أ) سطح دلالي ثانٍ لكل توكن، (ب) إعادة حساب تباين **ألوان المستأجر** على خلفية داكنة
(عقد التسعة ألوان يُعاد اشتقاقه لكل مستأجر)، (ج) مراجعة 68 مكوّنًا و19 لقطة axe.
**التقدير: 6–8 أيام ولا يخدم أي طلب مستخدم حالي.** التوصية: يبقى خارج النطاق، ويُوثّق كـRFC
في الموجة 9 بدل تنفيذه. إن قرر المالك العكس، هذا بند مستقل لا يُحشر في موجة.

### 4.4 الطباعة

عائلة واحدة (thmanyah sans) بوزنين متغيّرين، 154KB مضمّنة base64 وتُحمَّل بعد أول رسم.
المتبقي: **104 استخدامات بأحجام 12.5 / 13 / 13.5 / 14.5 / 15px** خارج الأدوار الستة
(‏25×13px، 21×12.5px، 7×15px…). الخطة: ترحيل **بالمكوّن لا بالبحث والاستبدال** — كل ملف
يُلمس يُحوَّل، مع لقطة بصرية قبل/بعد. البوابة تمنع أي قيمة جديدة <12px، فلا خطر رجوع.

### 4.5 المسافات ونصف القطر والظل

شبكة 8px (‏14 توكنًا من 2px إلى 96px) — لا تغيير. نصف القطر «صغير بقصد»: 6/10/14/20،
و`full` للشرائح فقط. الظل: `--shadow-float` وحده للعناصر الطافية، والبطاقات حدّية —
قاعدة مكتوبة، وتُضاف بوابة grep تمنع `shadow-*` جديدًا على `.card`.

### 4.6 المكوّنات — ما يُصلح

| المكوّن | الحالة | الإجراء |
|---|---|---|
| `.btn` / `.input` | 4 أنماط × 3 أحجام، 44px على اللمس | لا تغيير |
| `Modal` | `role=dialog` + `aria-modal` + `aria-labelledby` + Escape | يضاف `inert` للخلفية (بدل حجب التركيز يدويًا) |
| `Toggle` | 44px hit ring عبر `::before` | لا تغيير |
| `EmptyState` | مستخدم في 7 ملفات | يُعمَّم على التحليلات/المطبخ/سوبر أدمن |
| `Skeleton` | موجود + `loading.tsx` في 10 مسارات | يوحَّد شكل الهيكل مع كثافة كل شاشة |
| الحاويات | `.page` / `.page-wide` فقط | إضافة `<PageContainer variant>` لمنع `max-w-[…]` المحلي |
| الأيقونات | lucide-react، 24px، `stroke-width: 1.75` | تُثبَّت القاعدة في مكوّن `Icon` واحد بدل تمرير props |

## 5. UX/UI Pattern Library Plan

### 5.1 التسلسل والمسح البصري
لوحة التاجر كثيفة بقصد (14px / 1.5). القاعدة الحالية سليمة: عنوان صفحة واحد، عنوان قسم بـ12px،
بطاقات KPI بحدود لا ظلال. الناقص: **تمييز الصف «التالي» في الطلبات** (لون + وزن + موضع)،
وهو ما يمنع عين التاجر من مسح 25 صفًا.

### 5.2 الملاحظات والحالات
- تحميل: `loading.tsx` في 10 مسارات (بما فيها POS) + `SectionLoading` للأقسام. الناقص: هيكل
  مخصّص لجدول الطلبات (الحالي هيكل عام لا يشبه الصفوف، فيقفز التخطيط عند الوصول).
- فراغ: 7 شاشات بها `EmptyState`؛ الناقص: التحليلات (رسم فارغ يبدو معطلًا)، المطبخ (لا طلبات)،
  سوبر أدمن.
- أخطاء: `error.tsx` لكل نطاق + `error-categories.ts`. الناقص: رسالة واحدة موحّدة للشبكة
  (حاليًا تختلف بين المنيو واللوحة).
- صلاحيات: `store-unavailable` / `subscription-expired` موجودتان؛ الناقص حالة «موظف يحاول
  فتح شاشة مالك» → تُوجَّه لصفحة 403 مفهومة لا لصفحة بيضاء.

### 5.3 التنقل والـwayfinding
الشريط السفلي (هاتف) + السكة (تابلت) + الشريط الجانبي (سطح مكتب) — ثلاث حالات مغطاة.
**صفر breadcrumbs** اليوم، والعمق ثلاث مستويات (`/dashboard/orders/[id]`، `/dashboard/products/[id]`).
الإضافة: `Breadcrumbs` واحد يُستدعى من `layout` بنمط `الرئيسية / الطلبات / #1042`، مع
`aria-label="مسار التنقل"` و`<nav>`، وإخفاؤه على الهاتف حيث يعود زر الرجوع كافيًا.
مصدر الحقيقة: خريطة ثابتة في `src/lib/nav-map.ts` تُستخدم في الشريط والـbreadcrumbs معًا
(لا تُشتق من URL — يمنع «طلبات/طلبات»).

### 5.4 النماذج
`inputMode` مضبوط في 9 حقول أسعار/كميات. الفجوة: `aria-invalid` في **5 ملفات فقط**،
ولا `aria-describedby` يربط الخطأ بالحقل، ولا ملخّص أخطاء في النماذج الطويلة (تسجيل المتجر).
العقد المقترح:
```
<label for> + aria-invalid + aria-describedby="slug-error" + role="alert" عند الظهور
```
مع بوابة اختبار: كل `<input required>` في النماذج الثلاثة (login, register, onboarding)
يجب أن يحمل `aria-describedby` عند الخطأ.

### 5.5 الحركة
150–250ms، `ease-out` فقط، و`prefers-reduced-motion` يعطّل كل شيء (منفّذ عالميًا).
المتبقي: حركة الشريحة (bottom sheet) تتبع الإصبع — حاليًا `slide-up` ثابت. تُنفَّذ بـ
`translateY` + `transition` لا بـJS، وتُلغى كليًا عند `reduced-motion`.

### 5.6 قائمة فحص الوصول (المحدثة)
- [x] تباين 4.5:1 للنص و3:1 للحدود — محمي باختبارات
- [x] focus مرئي 2px + offset 2px على كل عنصر
- [x] `aria-modal` + Escape + إعادة التركيز في Modal
- [x] 44×44 لأي هدف لمسي (بوابة CI)
- [ ] `inert` لخلفية المودال

## 12. سجل التنفيذ — الموجة 6 (نُفِّذت 2026-10-23)

**الحالة:** مكتملة، عدا بند واحد مؤجَّل بقرار (اللقطات البصرية). الشاشات المسجّلة صارت مُقاسة
تخطيطيًا لأول مرة، وWebKit دخل البوابة.

| ما تغيّر | التفصيل |
|---|---|
| مسبار واحد | `e2e/lib/layout-probe.ts`: كود القياس استُخرج من `responsive.spec.ts` ليستخدمه الفحصان — 56 خلية عامة بقيت 56/56، فالتغيير سلوكيًا صفر |
| مصفوفة المسارات المسجّلة | `e2e/authed-responsive.spec.ts`: 8 شاشات × 5 مقاسات (320 · 768 · 1024 · 1280 · 640×512) = **40 خلية**، بمستأجر اختباري واحد يُنشأ ويُحذف في كل تشغيل |
| عقد التنقل | كل خلية على `/dashboard` تتحقق: شريط سفلي < 768، سكة 88px عند 768، شريط ≥ 200px عند 1024 — عقد الموجة 1 صار مُثبتًا لا مُدَّعى |
| WebKit | مشروع `webkit` (iPhone 13) + `e2e/ios.spec.ts`: ثلاث دعاوى — لوحة المنتج داخل visualViewport وبـ`dvh`، حقول ≥16px بلا تكبير، بلا تمرير أفقي |
| CI | `quality-watch.yml`: وظيفة webkit ليلية (قراءة فقط)، ووظيفة المصفوفة المسجّلة على `workflow_dispatch` فقط لأنها تكتب مستأجرًا مؤقتًا |
| أوامر | `npm run test:authed` · `npm run test:webkit` |

**ما كشفته المصفوفة فورًا (أُصلح):**
1. **درج مغلق يُحسب تجاوزًا.** عند 320 فشلت كل الشاشات على أزرار الدرج (`x=329`) لأن `translate-x-full` يخزنه خارج الشاشة. المسبار صار يستثني عنصرًا فقط إذا كان سلفه `aside`/`dialog` **بالكامل** خارج العرض — الدرج نصف المفتوح يبقى خطأً.
2. **مفتاح اللون في الإعدادات 40px.** `h-10` على `<input type=color>` ينتهك أرضية 44px على اللمس → صار `h-11`.
3. **قياس الاسم المتاح كان ناقصًا.** المسبار كان يقرأ `aria-label` والنص فقط، فيصنّف أي حقل مرتبط بـ`<label>` كزر أيقوني بلا اسم → أُضيف `labels[0]`.
4. **تحفّظات الشبكة.** تشغيلان انتهيا بـ38/40 بسبب `ERR_NETWORK_CHANGED` ثم تحويل إلى `/onboarding` (سباق قراءة بعد كتابة المستأجر) → إعادة محاولة واحدة لأخطاء الشبكة فقط، وإعادة فتح واحدة عند التحويل.
5. **تسريب مستأجر عند إيقاف التشغيل.** صف بلا `staff_members` لا يجده `cleanupTestUser` (المفتاح بريد) → `sweepStaleFixtures()` يحذف ما تجاوز ساعتين قبل كل تشغيل.

**القياس النهائي:** المصفوفة العامة **56/56** (50.9s) · المسجّلة **40/40** (46.3s) · vitest **482/482** ·
`tsc` 0 · `lint` 0 · `check-touch-targets` 140 ملفًا · `env:check` 36 · قاعدة البيانات بعد التشغيل:
**صفر** صفوف `e2e-matrix-*`.

**حدود معلنة:** WebKit نفسه لم يُشغَّل على هذا الجهاز — بناء Playwright لـUbuntu يطلب
`libicudata.so.74` و`libxml2.so.2` وArch يوفّر إصداریات أحدث، فالتشغيل المحلي استخدم نفس
الدعاوى على Chromium بمقاس iPhone 13. التنفيذ الفعلي على WebKit يقع في وظيفة CI التي تُثبّت
المتصفح بـ`--with-deps`.

**مؤجَّل بقرار:** اللقطات البصرية (6 شاشات × 3 مقاسات). السبب أن الشاشات المسجّلة تعرض بيانات
حية (أرقام طلبات، تواريخ)، فاللقطة تختلف بين تشغيلين بلا أي تغيير في الكود → بوابة حمراء كاذبة.
تحتاج خادم staging ببيانات مثبتة، وهو بند الموجة 4 في خطة الأداء لا الموجة 6.
