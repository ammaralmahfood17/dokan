# docs/history — التقارير التاريخية (لا تُقرأ كمواصفات)

هذا المجلد يحفظ **ما قيل وقتها**، وليس **ما هو صحيح الآن**. التقرير التاريخي يوثّق قرارًا أو تشخيصًا في لحظة
معيّنة؛ بعد شهرين يصبح بعضه خاطئًا بالضرورة. لذلك فُصل عن العقود الحيّة بدل أن يجاورها في الجذر — كان المهندس
الجديد يفتح `FIXES_REPORT.md` بجانب `ARCHITECTURE.md` ولا يعرف أيّهما يُصدَّق.

## القاعدة

| اقرأ هذا | لتعرف |
|---|---|
| `ARCHITECTURE.md` | بنية النظام الحالية — **محر وس آليًا** بواسطة `scripts/check-architecture-doc.mjs` |
| `AGENTS.md` | عقد الوكلاء والمطورين (ما يُمنع وما يُشترط قبل أي commit) |
| `DATA-MODEL.md` | نموذج البيانات الحالي |
| `DESIGN_SYSTEM.md` | نظام التصميم وقواعده |
| `docs/audit-2026-10/` | أدلّة التدقيق والأدلة المُتحقَّقة على الإنتاج (مرجع، ويُشار إليه من الكود) |
| **`docs/history/`** | تقارير مؤرّخة — **سياق، لا مواصفات** |

## ما في هذا المجلد

- `FIXES-REPORT.md` — قائمة إصلاحات في فترة التدقيق الأولى.
- `HARDENING-REPORT.md` — تقرير تقوية الأمان لتلك الفترة.
- `DESIGN-AUDIT-REPORT-2026-10.md` — تدقيق التصميم/الواجهة (2026-10).
- `APPLE-REVIEW-FIXES.md` — ملاحظات مراجعة iOS/Apple والإصلاحات المقابلة.

> أي قاعدة معمارية مستخلصة من هذه التقارير يجب أن تعيش في `ARCHITECTURE.md` أو في السكيل/الأدلة ذات الصلة —
> لا أن تُستشهد من هنا.
